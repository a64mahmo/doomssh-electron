# Troubleshooting

## High Resource Usage during Build

If your computer slows down or crashes when running `npm run electron:dist`, it's likely due to the high memory demands of compiling Next.js and packaging the application.

### Recommended Solutions

#### 1. Increase Node.js Memory Limit
By default, Node.js may not allocate enough memory for large builds. You can increase the heap size by setting the `NODE_OPTIONS` environment variable.

**On macOS/Linux:**
```bash
export NODE_OPTIONS="--max-old-space-size=4096"
npm run electron:dist
```

**On Windows (PowerShell):**
```powershell
$env:NODE_OPTIONS="--max-old-space-size=4096"
npm run electron:dist
```

#### 2. Prune Dependencies Before Packaging
To reduce the package size and build time, ensure you are only including production dependencies in your final bundle.

You can try running `npm prune --production` in the `frontend` directory before building the Electron app.

#### 3. Build Components Individually
Instead of running `npm run electron:dist`, try running the build steps one by one to isolate the resource usage:

1.  `npm run build` (Frontend)
2.  `npm run electron:build` (Electron)
3.  `npx electron-builder` (Packaging)

## Debugging & Diagnostics

### Bug Mode (Global Diagnostics)
If you encounter persistent errors with AI generation or file saving, you can enable **Bug Mode** to see detailed technical logs. Bug Mode is available in the **desktop app** only.

1.  Navigate to the **Main Dashboard**.
2.  Click the **Settings (Gear Icon)** in the bottom left.
3.  Toggle **Bug Mode** to ON.
4.  Detailed error toasts will now appear whenever a system failure occurs.

### Persistence Failures on Windows
If the application hangs or fails to save on Windows after adding a large photo or creating many jobs:
- Ensure you are running version **v0.3.0** or later.
- Check that your **Vault Folder** has write permissions.
- Enable **Bug Mode** to see the specific file-system error.

## Software Updates

### Manual Update Check
If you suspect you are missing an update or the auto-update notification didn't appear:
1.  Open **Settings** from the main dashboard.
2.  Click **Check for Updates**.
3.  If an update is available, you will see a progress bar.
4.  Once complete, click **Restart & Install Now**.

### Update Errors
If an update fails to download:
- Ensure you have a stable internet connection.
- Check that the application is not blocked by a firewall or antivirus.
- Enable **Bug Mode** to see the specific update error message.

## PDF Export

### The exported PDF differs from the preview
- **Desktop app:** the PDF is the HTML preview printed by Chromium, so content should match. Page breaks can differ slightly from the dashed guides in the preview: printing moves a section heading or an entry's first line onto the next page instead of splitting it.
- **Web build:** the download is generated by a separate renderer (`@react-pdf/renderer`), so small spacing differences from the preview are possible.

### Export times out or does nothing (desktop)
The export window waits up to 15 seconds for the page to finish rendering. If it times out:
- Check the terminal running the app for `PDF export error`.
- Very large embedded photos slow rendering — use a smaller image.

### Blank trailing page, or backgrounds print white
Both were fixed in the print styles. If you customize `app/print/[resumeId]/PrintClient.tsx` or `electron/main.ts`, keep `printBackground: true`, `@page { margin: 0 }`, and the rules that drop the page root's `min-height` and the last entry's bottom margin.

## Web (Browser) Build

### My data disappeared
The web build stores everything in this browser's IndexedDB. Clearing site data, using a private window, or switching browsers or devices shows an empty dashboard. Export anything you want to keep.

### AI buttons, Bug Mode or updates are missing
These need the desktop app. The browser Settings dialog intentionally shows only a storage note.

### The site behaves like the wrong build
Check the `NEXT_PUBLIC_APP_PLATFORM` **build** variable (`web` for the Cloudflare build). It is inlined when the site is built, so change it in the build settings and redeploy — setting it as a runtime variable or secret has no effect. See [Deployment](./deployment.md).

### "New Application" shows no fields in Safari
Fixed: in Safari the job dialog's form collapsed to zero height, so only the header, tabs and an overlapping Cancel/Save row were visible and saving did nothing. Update to the latest build. The dialog (`components/jobs/JobDetailDialog.tsx`) needs a definite height — avoid `h-fit` on a flex dialog whose body uses `flex-1 min-h-0`.

### Jobs or edits are lost after a reload
Fixed: saves made in quick succession used to be dropped. Update to the latest build. If it still happens, check the browser console for `Failed to save jobs` / `Failed to save resume`.
